# 汇川产品刷题工具开发整体规划与落地思路

> 版本：V1.0　|　适用范围：汇川技术工业自动化产品（伺服 / 变频器 / PLC / HMI / IO 系统）内部培训与渠道赋能
> 交付物：本规划文档 + 可运行工具（`index.html` 刷题端、`admin.html` 管理端、`data/*.json` 题库）

---

## 一、项目概述

### 1.1 项目背景

汇川技术工业自动化产品线覆盖变频器、伺服系统、可编程逻辑控制器（PLC）、HMI 人机界面、IO 系统等核心品类，产品系列多、迭代快、参数与选型逻辑专业性强。当前产品知识传递主要依赖线下培训、产品手册与师徒带教，存在四个突出矛盾：

| 现状问题 | 具体表现 | 业务影响 |
|----------|----------|----------|
| 产品知识零散 | 手册、课件、FAQ、现场经验分散在不同人手里 | 新人上手慢，销售讲不清卖点，工程师选型靠问人 |
| 培训无标准 | 培训内容与深度因人而异，无统一考核口径 | 培训效果无法复制，跨区域能力参差不齐 |
| 考核无量化 | 考试靠人工出卷、人工阅卷、Excel 统计 | 组织成本高，结果不可比、不可追溯 |
| 能力摸底无数据 | 不知道谁强在哪、弱在哪、哪类知识普遍缺失 | 培训投入无法精准投放，题库质量问题发现不了 |

### 1.2 项目定位

打造一套**汇川产品专属、实操场景专属、企业培训专属**的刷题与考核工具，做到：

- **专属**：题库 100% 围绕汇川五大品类真实产品系列（如伺服 SV660 系列、变频器 MD500/MD800 系列、PLC H5U/AM 系列、HMI IT7000 系列、IO GL20 系列等），题干即现场，答案可溯源到官方资料；
- **可用**：轻量化 B/S 架构，内网静态服务器即可部署，电脑与手机浏览器直接使用，可内嵌企业微信/钉钉；
- **可管**：题库全生命周期管理（导入 → 审核 → 上线 → 归档 → 统计），四角色权限隔离，涉密内容对外不可见；
- **可量化**：个人能力画像 + 团队/题库多维报表，让培训效果从"感觉"变成"数据"。

### 1.3 适用人群

| 人群 | 核心诉求 | 工具对应设计 |
|------|----------|--------------|
| 内部销售 | 快速掌握卖点、系列差异、竞品对比口径 | 初级难度为主，选型/方案类题目，`sales` 人群标注 |
| 技术工程师 | 选型计算、参数配置、通信组网、调试排故 | 中高级难度，参数配置/调试/故障排查题，`engineer` 标注 |
| 采购 | 选型比价、型号命名规则、规格参数与认证核对 | 客观题（参数 / 命名 / 认证类），`purchase` 标注 |
| 合作客户 / 代理商 | 产品认知、基础操作、对外赋能考试 | 仅公开密级题库（对外赋能版） |

## 二、核心开发目标

### 2.1 业务目标

1. **新人上岗周期压缩 30% 以上**：以标准化题库替代"口口相传"，新人可按初级题库自学 + 自测，导师只需带教疑难。
2. **培训效果可量化**：覆盖率、正确率、薄弱品类、考试通过率等指标自动沉淀，月度培训复盘有据可依。
3. **知识资产集中沉淀**：把散落在工程师脑子里的现场经验，通过"题目 + 解析 + 资料溯源"结构化沉淀进题库。
4. **渠道赋能标准化**：对外部客户/代理商开放公开题库与考试任务，输出统一的汇川产品认知标准。

### 2.2 产品目标

| 目标维度 | 量化指标（一期） |
|----------|------------------|
| 题库规模 | 五大品类各 ≥ 30 题，合计 ≥ 150 题，覆盖 5 种题型、3 个难度 |
| 题库质量 | 100% 题目具备解析；100% 具备资料溯源字段；涉密题占比 ≤ 15% |
| 功能完备 | 用户端 5 大模块 + 管理端 6 大模块全部可用 |
| 性能体验 | 单页首屏 ≤ 1.5s（纯静态无外部依赖）；答题交互无等待；支持 3000 题量规模不卡顿 |
| 多端适配 | 桌面 / 平板 / 手机自适应，最小适配宽度 360px |
| 部署成本 | 零后端依赖即可运行；企业版可平滑升级至带数据库的 B/S 架构 |

## 三、整体产品架构

### 3.1 分层架构

```
┌──────────────────────────────────────────────────────────────┐
│  接入层   浏览器（PC / 平板 / 手机）· 企业微信 / 钉钉工作台    │
│           单点登录（SSO）预留：CAS / OAuth2 / 企微免登         │
├──────────────────────────────────────────────────────────────┤
│  表现层   刷题端 index.html        管理端 admin.html          │
│           仪表盘 · 刷题 · 错题本 · 模拟考试 · 数据统计         │
│           题库管理 · 导入导出 · 审核上线 · 任务 · 报表 · 权限  │
├──────────────────────────────────────────────────────────────┤
│  应用层   组卷引擎   判题引擎   统计引擎   权限引擎            │
│           抽题策略 · 均衡组卷 · 客观自动判分 · 主观自评        │
├──────────────────────────────────────────────────────────────┤
│  数据层   题库数据（bank.js / data/*.json）                   │
│           学习数据（浏览器本地存储；企业版→ 数据库）           │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 数据分层设计

| 数据类别 | 内容 | 一期存储 | 企业版存储建议 |
|----------|------|----------|----------------|
| 题库数据 | 五大品类题目、选项、答案、解析、溯源、标签、人群、密级 | 静态文件 `assets/js/core/bank.js` | MySQL 表 `question` / `question_tag` |
| 用户数据 | 姓名、角色、部门 | 浏览器 local storage | 用户表 + 组织架构表，对接 HR/AD |
| 学习数据 | 作答记录、错题本、收藏、笔记 | 浏览器 local storage | `answer_log` / `wrong_book` 表 |
| 考试数据 | 试卷快照、作答、得分、用时 | 浏览器 local storage | `exam` / `exam_detail` 表 |
| 管理数据 | 题目状态、编辑覆盖、考试任务、操作日志 | 浏览器 local storage | 对应业务表 + `audit_log` |

> 一期采用"纯前端 + 本地存储"是为了**零部署成本、快速验证题库与流程**；数据层通过 `store.js` 单点封装，升级为后端接口时只需替换该模块，页面代码无需改动。

### 3.3 题库分类模型（三重维度）

```
品类维度：伺服系统 | 变频器 | PLC | HMI 人机界面 | IO 系统
场景维度：选型 · 接线安装 · 参数配置 · 通信组网 · 调试 · 故障排查 · 维护保养 · 方案应用
难度维度：初级（新人/销售）| 中级（工程师日常）| 高级（疑难/方案级）
题型维度：单选 | 多选 | 判断 | 简答 | 场景分析
人群维度：销售 | 技术 | 采购 | 合作客户
密级维度：公开 | 内部 | 涉密
```

## 五、技术选型方案

### 5.1 一期技术栈（已落地）

| 层次 | 选型 | 选型理由 |
|------|------|----------|
| 前端框架 | 原生 JavaScript（ES5+ 语法，IIFE 模块化，无构建） | 内网环境无外网、无 npm 源也能维护；无框架升级负担；新人可直接改 |
| 样式 | 原生 CSS3（CSS 变量 + Grid/Flex + 媒体查询） | 体积小、可读性高、无预处理器依赖 |
| 图表 | 手写 SVG 组件（环形、柱状、雷达、趋势、占比条） | 不引 ECharts 等大体积库，离线可用，首屏快 |
| 数据存储 | 浏览器 localStorage（`iqz.state.v1`）+ 静态题库文件 | 零后端、零部署成本；数据结构集中封装便于替换 |
| 题库格式 | JSON（`data/<品类>.json` → 构建为 `bank.js`） | 便于批量维护、版本管理、脚本校验 |
| 构建工具 | Node.js 脚本 `tools/build-bank.mjs`（零依赖） | 只用标准库，无需 npm install |
| 本地服务 | Node.js 静态服务器 `tools/serve.mjs` | 用于本地预览与内网验证 |
| 部署 | 任意静态服务器（Nginx / IIS / Apache / OSS） | 单目录拷贝即完成部署 |

### 5.2 企业版技术栈建议（二期可选升级）

| 层次 | 建议选型 | 说明 |
|------|----------|------|
| 后端 | Spring Boot 2.7 / 3.x（或 Node.js + NestJS） | 与汇川内部 Java 生态一致，团队易维护 |
| 数据库 | MySQL 8.0（题库、用户、考试） + Redis（会话、排行榜） | 通用成熟、运维成本低 |
| 前端 | 沿用本工具页面，仅替换 `store.js` 为 API 适配层 | 一期投入不浪费 |
| 认证 | 企业微信/钉钉免登 + CAS/OAuth2 单点登录 | 满足"内嵌工作台 + SSO"要求 |
| 部署 | 内网 Docker（2C4G 起）或独立服务器 + Nginx | 低配可用，便于横向扩容 |
| 文件 | 手册 PDF、视频存放于内网文件服务/OSS | 支撑"文档溯源"与后续"视频联动学习" |

## 七、题库建设核心规范

### 7.1 字段规范（工具强校验）

| 字段 | 取值要求 | 校验强度 |
|------|----------|----------|
| `id` | `<品类前缀>-<三位序号>`，如 `SRV-035`、`INV-014` | 必填、唯一 |
| `category` | `servo` / `inverter` / `plc` / `hmi` / `io` | 必填、枚举校验 |
| `type` | `single` / `multi` / `judge` / `short` / `scenario` | 必填、枚举校验 |
| `difficulty` | `1` 初级 / `2` 中级 / `3` 高级 | 必填、枚举校验 |
| `stem` | 题干自足无歧义；场景题须含现场背景、现象、待答问题 | 必填、长度校验 |
| `options` | 单选/多选必填（2–5 项）；判断/简答/场景为 `null` | 按题型校验 |
| `answer` | 单选 `["A"]`；多选 `["A","C"]`（≥2）；判断 `["T"]/["F"]`；简答/场景为参考答案文本 | 必填，答案键必须在选项内 |
| `analysis` | ≥ 40 字，须说明干扰项错在哪、现场易错点 | 必填、长度提示 |
| `source` | `{title, chapter, url}`，指向汇川官方手册/产品页 | 必填、缺失告警 |
| `tags` | 2–5 个知识点标签（系列名、场景） | 必填 |
| `roles` | `sales` / `engineer` / `purchase` / `partner` | 必填，缺失时默认 `engineer`；销售与采购只考查客观题 |
| `security` | `public` / `internal` / `confidential` | 必填、枚举校验 |

### 7.2 内容溯源要求

1. **唯一依据**：题干中出现的系列名、型号、参数、操作路径必须来自汇川官方手册、选型手册、样本或官网产品页，禁止编造型号与参数；
2. **可点击溯源**：每题 `source` 字段必须提供官方资料名称与章节，尽量附官方链接，学员在解析区可一键跳转核对；
3. **二手信息降级**：如引用渠道培训资料，须在解析中注明来源，且不得作为唯一依据；
4. **争议处理**：任何被 2 名以上工程师质疑的题目，先转"草稿"下线，核实后重新上线并在操作日志中留痕。

### 7.3 动态更新机制

| 触发场景 | 更新动作 | 责任人 | 时限 |
|----------|----------|--------|------|
| 新产品/新系列发布 | 补充对应系列题目 ≥ 5 题 | 产品培训讲师 | 发布后 2 周内 |
| 产品固件/手册版本更新 | 核对受影响题目参数，必要时修订解析 | 讲师 + 产品线工程师 | 更新后 1 个月内 |
| 错题率异常（某题错误率 > 70%） | 复核题干歧义与答案正确性 | 题库管理员 | 数据出现后 1 周内 |
| 现场高频故障新模式 | 沉淀为场景分析题 | 技术 + 讲师 | 案例确认后 2 周内 |
| 政策/合规变化 | 下线或修订相关题目 | 超级管理员 | 即时 |

### 7.4 分层适配与解析要求

- **分层**：初级题面向"知道是什么/怎么选"，中级题面向"怎么配/怎么调"，高级题面向"为什么错/怎么解"，同一知识点可在三个难度各设一题形成梯度；
- **解析三段式**：① 正确答案为什么对；② 每个干扰项错在哪（尤其是"别的系列才有的功能""相似参数混淆"）；③ 现场经验提示（如"现场遇到站号冲突应从主站组态查起"）；
- **主观题评分锚点**：简答/场景题的参考答案采用分条要点式，便于学员自评与讲师复核。

## 八、风险预判与解决方案

### 8.1 题库误差风险（题目错误、答案争议、参数过期）

| 维度 | 措施 |
|------|------|
| 事前预防 | 强制执行字段校验脚本（`build-bank.mjs --check`）；解析必须写清干扰项错因；涉密与关键参数题必须附官方章节溯源 |
| 事中控制 | 题目支持"草稿 / 上线 / 归档"三态，争议题一键转草稿下线；导入前生成校验报告，错误题目不允许入库 |
| 事后修正 | 每题保留操作日志；错题率 > 70% 自动进入复核清单（报表页"逐题正确率"）；题库按品类分批版本化，可整体回滚 |
| 责任机制 | 明确"谁出题谁负责、讲师审核、超管终审"的三级责任链，配套《题库运营管理办法》 |

### 8.2 使用率低风险（推不动、没人练）

| 维度 | 措施 |
|------|------|
| 降低门槛 | 内嵌企业微信/钉钉工作台一键进入；手机端底部导航 + 单手可操作；免注册（选择身份即用） |
| 即时正反馈 | 即时判题、解析秒出、今日目标环形进度、连续学习天数；练习小结直观展示进步 |
| 与考核挂钩 | 培训讲师按角色下发考试任务，成绩纳入新人上岗认证与渠道赋能评级 |
| 内容吸引力 | 场景分析题取自真实现场案例；错题本让"练了就有用"；收藏夹支持个人重点整理 |
| 运营节奏 | 每月一次主题闯关（如"伺服选型月"），榜单与积分在二期排行榜功能中落地 |

### 8.3 适配卡顿风险（多端、低配、大题库）

| 维度 | 措施 |
|------|------|
| 体积控制 | 纯静态无第三方库，首屏仅 5 个本地文件；图表用轻量 SVG 而非图表库 |
| 题库规模 | 一期 3000 题量级（bank.js 约 2–3 MB）分品类按需加载；企业版改为后端分页 + 索引查询 |
| 渲染性能 | 列表分页（20 条/页）、原生 DOM 直出、无虚拟 DOM 开销；答题仅重绘题卡区域 |
| 低端设备 | 响应式断点覆盖 360px 起；动画仅用 CSS transform/opacity；无视频自动播放 |
| 老浏览器 | 语法保持 ES5+ 兼容（不用可选链、模块化 script），覆盖内网常见的老版本内核浏览器 |

### 8.4 数据泄露风险（涉密题库外流、成绩数据泄露）

| 维度 | 措施 |
|------|------|
| 内容分级 | 题目密级三档（公开/内部/涉密），对外部客户/代理商角色**在数据加载层过滤**，涉密题不下发到前端 |
| 权限最小化 | 四级角色权限矩阵集中定义（`ROLE_DEFS`），管理端功能按权限渲染且后端（企业版）二次校验 |
| 传输安全 | 企业版全站 HTTPS；内网部署限制访问网段；静态资源禁止目录列举 |
| 数据脱敏 | 团队报表按权限展示，外部角色仅见个人数据；导出功能按角色限制（员工/C 端不可导出题库） |
| 审计留痕 | 题目增删改、导入导出、任务发布全部写入操作日志，支持导出审计 |
| 设备侧 | 本地存储仅保存必要学习数据；提供"清空学习记录 / 恢复出厂"自助操作，离职设备可远程清理（企业版） |

## 十、方案总结

本方案围绕汇川工业自动化五大核心品类，交付了一套**可立即使用、可持续运营、可平滑升级**的产品刷题工具：

1. **专属性强**：题库、场景、解析全部围绕汇川真实产品系列与现场业务，题目可溯源到官方资料，区别于通用工控题库工具；
2. **功能闭环**：用户端"刷题 → 错题 → 强化 → 考试 → 数据"形成学习闭环；管理端"导入 → 审核 → 上线 → 任务 → 报表"形成运营闭环；
3. **权限清晰**：四级角色 + 三档密级，数据层隔离，满足内部培训与对外赋能的双重场景；
4. **成本可控**：一期零后端依赖，静态部署即可上线验证；二期按需升级为带数据库的 B/S 架构，前端资产完全复用；
5. **风险可控**：针对题库误差、使用率、适配性能、数据泄露四类核心风险，均有可落地的机制与责任人安排。

**下一步建议**：先用本工具（`index.html` + `admin.html`）在 1 个部门做两周灰度试用，用"逐题正确率"数据筛出质量最差的 10 道题修订，再启动全区域推广 —— 让题库质量在使用中收敛，而不是在上线前空想。
