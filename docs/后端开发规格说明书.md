# 汇川产品刷题工具 · 后端开发规格说明书

**版本**：V1.0　|　**数据库**：MySQL 8.0　|　**架构**：B/S（RESTful API + 现有前端页面）
**适用范围**：将现有纯前端刷题工具（`inovance-quiz/`）后端化，前端页面**不重新开发**，仅替换数据访问层

## 文档说明

### 读者与用途

| 读者 | 用途 |
|------|------|
| 后端开发 | 按本文档直接建表、实现接口 |
| 前端开发 | 按第三章接口清单编写 `api-store.js` 适配层 |
| 项目经理 | 按第五章三阶段计划排期与验收 |

### 与现有前端的关系（重要约束）

现有前端 `assets/js/app.js` 与 `assets/js/admin.js` **全部通过 `IqStore.*` 访问数据**，页面层不含任何存储细节。因此后端化只需：

```
现有：页面 → IqStore（localStorage）
后端化：页面 → IqStore（改名 api-store.js）→ RESTful API → MySQL
```

**页面组件、图表、判题交互、样式均无需改动**，仅需替换 `assets/js/core/store.js` 一个文件，并新增登录页的账号密码输入（现为"选择身份"）。

# 一、MySQL 建表 SQL 脚本

## 1.1 通用设计约定

| 项 | 约定 |
|----|------|
| 引擎 / 字符集 | `InnoDB` / `utf8mb4`（题目含中文与特殊符号，必须 utf8mb4） |
| 主键 | `BIGINT UNSIGNED AUTO_INCREMENT` |
| 时间 | `DATETIME`，统一存 **UTC+8 本地时间**，接口返回 `yyyy-MM-dd HH:mm:ss` |
| 软删除 | 业务表带 `deleted_at`（NULL=有效），**不使用物理删除**，保证审计可追溯 |
| 扩展字段 | 每张业务表预留 `ext_json JSON NULL`，新增需求优先走扩展字段，避免频繁 DDL |
| 枚举 | 使用 `ENUM` 并配中文注释；**取值与前端严格一致**，避免联调时映射错乱 |

**五大品类固定为**：`servo`(伺服) / `inverter`(变频器) / `plc`(PLC) / `hmi`(HMI) / `io`(IO系统)，不新增。
**难度固定为**：`beginner`(入门) / `intermediate`(中级) / `advanced`(高级)。

## 1.2 user 用户表

```sql
-- ============================================================
-- 用户表：四种角色统一存储，权限由 role 决定（见 §4.1）
-- ============================================================
CREATE TABLE `user` (
  `id`            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '用户主键',
  `username`      VARCHAR(64)     NOT NULL                COMMENT '登录账号（唯一；3-64位字母数字及 _ . @ -）',
  `password_hash` VARCHAR(255)    NOT NULL                COMMENT '密码哈希（BCrypt/Argon2id，严禁明文或MD5）',
  `name`          VARCHAR(64)     NOT NULL                COMMENT '姓名或工号（页面显示用）',
  `role`          ENUM('super_admin','trainer','employee','partner')
                                  NOT NULL DEFAULT 'employee'
                                  COMMENT '角色：超级管理员/培训讲师/内部员工/代理商客户',
  `dept`          VARCHAR(128)    NOT NULL DEFAULT ''     COMMENT '部门或渠道名称（报表按此维度聚合）',
  `phone`         VARCHAR(32)     NULL                    COMMENT '手机号（预留：找回密码、短信通知）',
  `email`         VARCHAR(128)    NULL                    COMMENT '邮箱（预留）',
  `status`        TINYINT         NOT NULL DEFAULT 1      COMMENT '账号状态：1启用 0停用（停用后登录拒绝）',
  `last_login_at` DATETIME        NULL                    COMMENT '最近登录时间',
  `login_count`   INT UNSIGNED    NOT NULL DEFAULT 0      COMMENT '累计登录次数（预留：活跃度分析）',
  `created_by`    BIGINT UNSIGNED NULL                    COMMENT '创建人ID（管理端建号时记录）',
  `created_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at`    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_at`    DATETIME        NULL                    COMMENT '软删除时间（NULL=有效）',
  `ext_json`      JSON            NULL                    COMMENT '扩展字段（预留：企业微信userid、钉钉id、SSO唯一标识、岗位标签等）',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_username` (`username`),
  KEY `idx_user_role_status` (`role`, `status`),
  KEY `idx_user_dept` (`dept`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='用户表';

-- 说明：如需"软删除后复用同一账号名"，请在软删除时把 username 改写为
--       原值 + '__deleted_' + id，再写入 deleted_at。
```

## 1.3 question 题目主表（核心）

```sql
-- ============================================================
-- 题目主表：题库唯一数据源
-- 权限控制三要素：security(密级) + status(状态) + audience(适用人群)
-- ============================================================
CREATE TABLE `question` (
  `id`             BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '题目主键',
  `question_no`    VARCHAR(32)     NOT NULL                COMMENT '业务题号（唯一，如 SRV-001 / INV-034）',
  `category`       ENUM('servo','inverter','plc','hmi','io')
                                   NOT NULL                COMMENT '产品品类：伺服/变频器/PLC/HMI/IO系统（固定五项）',
  `type`           ENUM('single','multi','judge','fill','short','scenario')
                                   NOT NULL                COMMENT '题型：单选/多选/判断/简答/场景分析',
  `difficulty`     ENUM('beginner','intermediate','advanced')
                                   NOT NULL DEFAULT 'beginner'
                                   COMMENT '难度：入门/中级/高级',
  `security`       ENUM('public','internal','confidential')
                                   NOT NULL DEFAULT 'public'
                                   COMMENT '密级（权限核心字段）：公开=客户可见 / 内部=仅内部员工 / 涉密=仅超管与讲师',
  `status`         ENUM('draft','published','archived')
                                   NOT NULL DEFAULT 'draft'
                                   COMMENT '状态：草稿(不参与组卷)/已上线/已归档(下线保留)',
  `stem`           TEXT            NOT NULL                COMMENT '题干（场景题需含现场背景、现象与待答问题）',
  `options`        JSON            NULL                    COMMENT '选项：[{"key":"A","text":"..."}]；判断/简答/场景题为 NULL',
  `answer`         JSON            NOT NULL                COMMENT '答案：客观题为key数组如 ["A"] / ["A","C"] / ["T"]；主观题为纯文本字符串',
  `explanation`    TEXT            NULL                    COMMENT '专业解析（要求说明干扰项错在哪，前端解析区直接展示）',
  `source_title`   VARCHAR(255)    NULL                    COMMENT '资料溯源-官方资料名称，如《SV660N系列伺服用户手册》',
  `source_chapter` VARCHAR(255)    NULL                    COMMENT '资料溯源-章节或页码',
  `source_url`     VARCHAR(500)    NULL                    COMMENT '资料溯源-官方链接（前端可点击跳转）',
  `tags`           JSON            NULL                    COMMENT '知识点标签数组，如 ["SV660","选型","EtherCAT"]',
  `audience`       JSON            NULL                    COMMENT '适用人群数组：["sales","engineer","purchase","partner"]',
  `score_weight`   DECIMAL(4,2)    NOT NULL DEFAULT 1.00   COMMENT '分值权重：单选1 / 多选1.5 / 判断1 / 简答2 / 场景3',
  `usage_count`    INT UNSIGNED    NOT NULL DEFAULT 0      COMMENT '累计作答次数（冗余统计，用于组卷热度与报表）',
  `right_count`    INT UNSIGNED    NOT NULL DEFAULT 0      COMMENT '累计答对次数（冗余统计，错题率榜单 = 1-right/usage）',
  `version`        INT UNSIGNED    NOT NULL DEFAULT 1      COMMENT '版本号（预留：题目修订追踪）',
  `created_by`     BIGINT UNSIGNED NULL                    COMMENT '创建人ID',
  `updated_by`     BIGINT UNSIGNED NULL                    COMMENT '最后修改人ID',
  `created_at`     DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at`     DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_at`     DATETIME        NULL                    COMMENT '软删除时间（NULL=有效）',
  `ext_json`       JSON            NULL                    COMMENT '扩展字段（预留：关联视频、手册页码锚点、AI生成来源、审核意见等）',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_question_no` (`question_no`),
  KEY `idx_question_filter` (`category`,`type`,`difficulty`,`security`,`status`),
  KEY `idx_question_status` (`status`,`deleted_at`),
  KEY `idx_question_security` (`security`,`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='题目主表';
```

## 2.4 后端 Excel 批量导入业务逻辑

### 2.4.1 处理流程（7 步）

```
① 接收文件
   POST /api/admin/questions/import   multipart/form-data
   ├─ file: .xlsx / .xls / .csv
   └─ mode: upsert(默认，存在即更新) | insert_only(跳过已存在) | dry_run(只校验不入库)

② 格式校验
   ├─ 文件大小 ≤ 10MB、行数 ≤ 2000（超限返回 400）
   ├─ 表头逐列比对模板，缺列直接整体拒绝（避免"错位导入"污染题库）
   └─ 空行跳过；公式单元格取其缓存值

③ 逐行解析与字段校验（单行失败不影响其它行）
   ├─ 枚举映射：中文→英文枚举（伺服→servo、单选题→single、中级→intermediate、内部→internal……）
   ├─ 题号：格式 + 前缀与品类一致性（SRV 前缀必须是 servo）
   ├─ 题型相关：单选/多选必须有 2–5 个选项；判断/简答/场景不得有选项
   ├─ 答案：客观题答案键必须都在选项中；多选题答案 ≥ 2 项；单选题恰好 1 项；
   │        判断题归一化为 T/F；简答与场景题答案必须是文本（长度 ≥ 5）
   ├─ 分值权重：留空则按题型写默认值
   └─ 错误分级：ERROR（该行丢弃）/ WARNING（放行但记录，如解析过短、缺资料链接）

④ 冲突处理
   ├─ 按 question_no 查库
   ├─ mode=upsert  → 存在则 UPDATE（version+1，写 updated_by），不存在则 INSERT
   ├─ mode=insert_only → 存在则计入 skipped
   └─ 题库内自重复（同一文件内题号重复）→ 后者判 ERROR

⑤ 事务写入
   ├─ 整个批次放在一个事务；单行失败不回滚成功行（逐行 savepoint）
   ├─ 成功后批量更新 question.usage_count/right_count（若导入含历史统计）
   └─ 写入 audit_log：action=question.import，details={总数,新增,更新,跳过,错误数,文件名,操作人}

⑥ 返回导入报告（前端"导入校验报告"面板直接渲染）

⑦ dry_run 模式：完整跑 ②③④，只回滚不提交，用于"先看看有多少错"
```

|------|------|
| `code` | 0=成功；非 0 见下表 |
| `message` | 成功为 `ok`，失败为可直接展示给用户的中文提示 |
| `data` | 业务数据；无数据时为 `null` |

**前端适配**：`api-store.js` 中统一解包 —— 成功取 `data`，`code!=0` 时抛错并由页面 `catch` 弹 Toast。这一处适配即完成，页面代码不变。

### 3.1.2 业务错误码

| code | HTTP | 含义 | 前端表现 |
|-----:|-----:|------|----------|
| 0 | 200 | 成功 | — |
| 1001 | 400 | 参数校验失败 | Toast 显示 `message` |
| 1002 | 401 | 未登录或登录已过期 | 跳登录页 |
| 1003 | 403 | 无权限（含越权访问涉密题） | Toast "无权访问" |
| 1004 | 404 | 资源不存在 | Toast |
| 1005 | 409 | 唯一键冲突（题号/账号重复） | Toast |
| 1006 | 429 | 请求过于频繁（预留限流） | Toast 稍后重试 |
| 2001 | 500 | 服务内部错误 | Toast "服务异常" |

### 3.1.3 认证与分页

- **认证**：请求头 `Authorization: Bearer <token>`；token 为 JWT（建议有效期 2h + 刷新令牌 7d），载荷含 `userId` `role` `securityScope`；
- **分页**：请求 `?page=1&page_size=20`（`page_size` 上限 200），响应 `data` 内附 `page` `page_size` `total`；
- **时间格式**：`yyyy-MM-dd HH:mm:ss`。

### 4.1.2 密级过滤：必须落在 SQL 层

**核心原则：越权题目绝不能进入响应体**，而不是"查出来再在前端隐藏"。

```java
// 1) 角色 → 可见密级集合（唯一权威来源，禁止散落在各业务代码里）
public List<String> securityScopeOf(String role) {
    switch (role) {
        case "super_admin":
        case "trainer":      return List.of("public", "internal", "confidential");
        case "employee":     return List.of("public", "internal");
        case "partner":      return List.of("public");
        default:             return List.of("public");
    }
}

// 2) 所有题库查询统一走这个方法，禁止绕过
public List<Question> listVisibleQuestions(Long userId, QuestionQuery q) {
    List<String> scope = securityScopeOf(currentRole(userId));
    return questionMapper.selectByQuery(q, scope);   // scope 进 SQL 的 IN 条件
}
```

```xml
<!-- 3) MyBatis 片段：密级与状态过滤写死在 SQL 里 -->
<select id="selectByQuery" resultMap="QuestionMap">
  SELECT id, question_no, category, type, difficulty, security, stem, options, score_weight
    FROM question
   WHERE deleted_at IS NULL
     AND status = 'published'
     AND security IN
     <foreach collection="scope" item="s" open="(" separator="," close=")">#{s}</foreach>
     <if test="category != null">   AND category   = #{category}   </if>
     <if test="difficulty != null"> AND difficulty = #{difficulty} </if>
     <if test="type != null">       AND type       = #{type}       </if>
   ORDER BY RAND()
   LIMIT #{count}
</select>
```

### 4.1.3 必须做密级校验的 7 个出口（自查清单）

| # | 出口 | 风险 | 校验方式 |
|---|------|------|----------|
| 1 | 组卷抽题 `POST /api/practice/paper` | 抽到涉密题 | SQL 过滤 + 请求中 `categories` 与权限取交集 |
| 2 | 题目详情 `GET /api/questions/{id}` | 直接改 id 越权读题 | 读取后校验 `security ∈ scope`，否则 403 |
| 3 | 考试开考 `POST /api/exams/start` | 同上 | 同 1 |
| 4 | 错题本 `GET /api/wrong-book` | 用户早期有权限、后期降级后仍能看到 | **查询时联表 question 校验密级**，不可只按 user_id 查 |
| 5 | 收藏 `GET /api/favorites` | 同上 | 同 4 |
| 6 | 考试报告 `GET /api/exams/{id}/report` | 历史答卷含涉密题 | 按快照题号回溯校验；权限不足时隐藏题干与解析 |
| 7 | 管理端接口 `GET /api/admin/questions` | 越权查看涉密题 | 仅 `bank.read` 且按角色密级过滤 |

> **重点提醒**：第 4、5 项是最容易漏的 —— 角色降级（如员工离职转为外部客户）后，历史错题/收藏里的涉密题必须同步不可见。

### 4.1.4 越权返回策略

- 命中越权：返回 `403` + `{"code":1003,"message":"无权访问该题目"}`；
- **不要返回 404 伪装**（虽然更隐蔽，但会让排查困难）；企业内网环境以可排查优先；
- 所有越权尝试写 `audit_log`（`action=security.denied`），便于发现异常扫描行为。

## 4.2 薄弱知识点推荐逻辑（对应【针对薄弱项强化练习】）

### 4.2.1 算法（三步）

```
第 1 步：算每个品类的个人正确率
   rate(category) = 该品类答对次数 / 该品类总作答次数   （见 §4.3 SQL）

第 2 步：判定"薄弱品类"
   薄弱条件：answered >= 5 次  且  rate < 60%
   排序：按 rate 升序（最弱的排最前）
   若没有任何品类满足 → 退化为"未做过的题优先"策略

第 3 步：从薄弱品类中抽题（保证题型覆盖）
   抽题优先级：
     ① 我答错过的题（wrong_book.status='open'）        —— 权重 3
     ② 我做错过的知识点标签（tags 命中历史错误标签）    —— 权重 2
     ③ 我从未做过的题                                  —— 权重 2
     ④ 其它（做对过的题，用于巩固）                     —— 权重 1
   抽题规则：
     - 单个品类占比不超过 60%（避免一次练习全是 PLC）
     - 各题型按题库内比例分配（单选/多选/判断/简答/场景）
     - 已在本会话出现过的题不重复
```

### 4.2.2 参考 SQL

```sql
-- ① 找出用户的薄弱品类（正确率 < 60% 且作答 >= 5 次）
SELECT category,
       COUNT(*)                                   AS answered,
       SUM(is_correct = 1)                        AS right_cnt,
       ROUND(SUM(is_correct = 1) / COUNT(*) * 100, 1) AS rate
  FROM user_answer
 WHERE user_id = :userId
   AND is_correct IS NOT NULL
 GROUP BY category
HAVING answered >= 5 AND rate < 60
 ORDER BY rate ASC;

-- ② 在某薄弱品类中优先抽"未掌握错题"
SELECT q.id, q.question_no, q.type, q.difficulty
  FROM question q
  JOIN wrong_book w ON w.question_id = q.id AND w.user_id = :userId AND w.status = 'open'
 WHERE q.status = 'published' AND q.deleted_at IS NULL
   AND q.security IN (:scope)
   AND q.category = :weakCategory
 ORDER BY w.wrong_count DESC, w.last_wrong_at ASC
 LIMIT :n;

-- ③ 补齐：该品类中用户未做过的题
SELECT q.id
  FROM question q
  LEFT JOIN user_answer ua ON ua.question_id = q.id AND ua.user_id = :userId
 WHERE q.status = 'published' AND q.deleted_at IS NULL
   AND q.security IN (:scope)
   AND q.category = :weakCategory
   AND ua.id IS NULL
 ORDER BY RAND()
 LIMIT :m;
```

### 4.2.3 接口

见 §3.3.3 `GET /api/dashboard/recommend?strategy=weak`；刷题页点击【针对薄弱项强化练习】时，前端以 `POST /api/practice/paper` + `{"mode":"weak"}` 调用，服务端复用本节算法组卷（`mode=weak` 时**忽略客户端传入的 categories**，由服务端按薄弱算法决定范围）。

## 4.3 雷达图五大品类正确率计算逻辑

### 4.3.1 计算公式

```
品类正确率 rate = 该品类【已判定】作答中 is_correct=1 的记录数
                ────────────────────────────────────────────── × 100%
                     该品类【已判定】作答记录总数（is_correct IS NOT NULL）

覆盖率 coverage = 该品类【已练过】的题目数 / 该品类对我可见的题目总数 × 100%
```

三条必须遵守的口径约定：

1. **分母排除主观题待自评记录**（`is_correct IS NULL`）—— 否则未自评的主观题会被算作"错"，人为拉低正确率；
2. **未作答品类返回 `null` 而不是 0** —— 前端雷达图用 `null` 判定"留空"，用 0 会画成一个错误的凹点；
3. **统计按次数而非按题** —— 同一题错 3 次算 3 次错误（体现真实掌握程度）。

### 4.3.2 参考 SQL

```sql
-- 一眼出全五个品类的正确率（无数据的品类不会出现在结果里，Java 层补 null）
SELECT ua.category,
       COUNT(*)                                        AS answered,
       SUM(ua.is_correct = 1)                          AS right_cnt,
       ROUND(SUM(ua.is_correct = 1) / COUNT(*) * 100, 1) AS rate
  FROM user_answer ua
 WHERE ua.user_id = :userId
   AND ua.is_correct IS NOT NULL
 GROUP BY ua.category;

-- 覆盖率（分子：练过的题数；分母：该用户可见题数，按密级过滤）
SELECT q.category,
       COUNT(DISTINCT q.id) AS total,
       COUNT(DISTINCT CASE WHEN p.seen > 0 THEN q.id END) AS seen
  FROM question q
  LEFT JOIN (SELECT question_id, COUNT(*) AS seen FROM user_answer WHERE user_id = :userId GROUP BY question_id) p
         ON p.question_id = q.id
 WHERE q.status = 'published' AND q.deleted_at IS NULL
   AND q.security IN (:scope)
 GROUP BY q.category;
```

### 4.3.3 Java 层组装（保证五轴齐全）

```java
Map<String, CategoryStat> statMap = mapper.selectCategoryRate(userId);   // 可能只有 3 个品类
List<RadarItem> radar = new ArrayList<>();
for (String cat : List.of("servo", "inverter", "plc", "hmi", "io")) {     // 固定五轴顺序
    CategoryStat s = statMap.get(cat);
    radar.add(new RadarItem(cat, nameOf(cat),
        s == null ? null : s.getRate(),      // 未作答 → null（前端留空）
        s == null ? 0 : s.getAnswered(),
        coverageOf(cat)));
}
```

## 4.4 判题必须上移后端（重要）

现有前端在浏览器里判题，后端化后**必须改为服务端判题**，理由：

| 风险 | 说明 |
|------|------|
| 答案泄露 | 若组卷接口返回 `answer`，学员 F12 即可看到全部答案 |
| 成绩篡改 | 前端计算的分数可被改造成任意值提交 |
| 密级绕过 | 前端过滤可被绕过，涉密题一旦下发即已泄露 |

**因此三条硬规则**：

1. 组卷/开考接口（§3.4.1、§3.5.6）返回的题目**不含 `answer` 与 `explanation`**；
2. 判分逻辑（含题型分值 1/1.5/1/1.5/2/3、多选全对才得分、填空题逐空比对）在后端实现，前端只展示结果；
3. 练习模式的解析由**提交答案接口**返回（§3.4.2），考试模式的解析由**报告接口**在交卷后返回（§3.5.10）。

## 4.5 自动加入错题本规则

### 4.5.1 触发规则表

| 场景 | `is_correct` | 对 `wrong_book` 的动作 |
|------|:------------:|------------------------|
| 练习/考试答错（客观题） | 0 | **upsert**：存在则 `wrong_count+1`、更新 `last_wrong_at`、`status='open'`；不存在则插入 |
| 练习/考试答对，且错题本中状态为 `open` | 1 | `status='mastered'`、`mastered_at=now`（**自动移出待攻克列表**） |
| 练习/考试答对，错题本中不存在 | 1 | 不写入错题本 |
| 主观题自评"答错" | 0 | 同第一条 |
| 主观题自评"答对" | 1 | 同第二条 |
| 已 `mastered` 的题再次答错 | 0 | `status` 回到 `open`，`wrong_count+1`（**重新进入待攻克**） |
| 用户手动移出错题本 | — | 直接删除该行（前端"移出"按钮） |

### 4.5.2 参考实现

```sql
-- upsert（MySQL 语法），在答题事务内执行
INSERT INTO wrong_book
  (user_id, question_id, question_no, category, wrong_count, last_wrong_answer, first_wrong_at, last_wrong_at, status)
VALUES
  (:userId, :questionId, :questionNo, :category, 1, :userAnswerJson, NOW(), NOW(), 'open')
ON DUPLICATE KEY UPDATE
  wrong_count       = wrong_count + 1,
  last_wrong_answer = VALUES(last_wrong_answer),
  last_wrong_at     = NOW(),
  status            = 'open',
  mastered_at       = NULL;

-- 重做正确 → 标记已掌握（仅当当前为 open）
UPDATE wrong_book
   SET status = 'mastered', mastered_at = NOW()
 WHERE user_id = :userId AND question_id = :questionId AND status = 'open';
```

### 4.5.3 事务边界

答题接口的写操作必须在一个事务内完成，保证三张表一致：

```
BEGIN;
  1. INSERT user_answer（答题记录）
  2. UPDATE question SET usage_count = usage_count + 1 [, right_count + 1]
  3. INSERT ... ON DUPLICATE KEY UPDATE wrong_book   /  或 UPDATE 转 mastered
  4. UPDATE question 冗余统计（可选，异步亦可）
COMMIT;
```

> 若第 3 步失败而 1、2 步提交，会出现"答错了但错题本没收录"的数据不一致 —— 这是最容易产生用户投诉的点，务必放在同一事务。
