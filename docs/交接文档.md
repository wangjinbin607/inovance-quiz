## 0. 一分钟了解

这是一个**面向汇川工业自动化五大品类（伺服 / 变频器 / PLC / HMI / IO 系统）的网页版刷题与考核工具**，共 **300 道题**，含刷题端与管理后台两个页面。

| 项目 | 事实 |
|------|------|
| 技术栈 | 原生 HTML + CSS + JavaScript（ES5+ 语法，**无框架、无构建、无 npm 依赖、无 CDN**） |
| 数据存储 | 浏览器 localStorage（键 `iqz.state.v1`）+ 静态题库文件 |
| 后端 | **无**。纯静态，拷目录即可部署 |
| 代码量 | 约 4400 行（不含题库数据），核心 6 个 JS 文件 |
| 题库 | **986 题** = 伺服 407 · 变频器 381 · PLC 66 · HMI 66 · IO 66（五批构建：首批 34 + 扩充 26 + 填空 6 + 内部选型考卷 41/15 + **技术题库 600 题**），全部经汇川官网与官方手册核实 |
| 浏览器要求 | Chromium 系 / Edge / Chrome / 360 极速模式；支持 `file://` 直开 |

**最重要的一句话**：接手时请连整个 `inovance-quiz/` 目录一起接收，不要只拿 `docs/` 里的文档 —— 文档描述的能力全部由该目录内的代码实现。

## 3. 架构与数据流

### 3.1 分层

```
┌─ 页面层 ────────────────────────────────────────────────┐
│ index.html  →  app.js    （刷题端：仪表盘/刷题/错题/考试/统计）│
│ admin.html  →  admin.js  （管理端：题库/导入/审核/任务/报表）  │
└───────────────────────┬─────────────────────────────────┘
                        │ 均通过全局命名空间调用（无模块打包）
┌─ 引擎层 ───────────────┴─────────────────────────────────┐
│ engine.js → IqBank（题库聚合/筛选）+ IqEngine（组卷/判题/统计）│
│ ui.js     → IqUI（图标/Toast/模态框/SVG 图表/CSV/下载）      │
└───────────────────────┬─────────────────────────────────┘
┌─ 数据层 ───────────────┴─────────────────────────────────┐
│ store.js → IqStore（状态 + localStorage + 权限 + 密级裁决）  │
│ bank.js  → window.INOVANCE_BANK（构建产物的内置题库数组）     │
└──────────────────────────────────────────────────────────┘
```

**依赖方向严格单向**：页面 → 引擎 → 数据层。数据层不反向依赖任何页面，这是二期换后端的关键设计。

### 3.2 脚本加载顺序（改 `index.html` 时必须遵守）

```html
<script src="assets/js/core/store.js"></script>   <!-- 1. 数据与权限 -->
<script src="assets/js/core/bank.js"></script>    <!-- 2. 题库产物 -->
<script src="assets/js/core/engine.js"></script>  <!-- 3. 引擎（依赖 1、2） -->
<script src="assets/js/ui.js"></script>           <!-- 4. 组件 -->
<script src="assets/js/app.js"></script>          <!-- 5. 页面 -->
```

### 3.3 全局命名空间（浏览器控制台可直接调用，调试利器）

| 命名空间 | 文件 | 常用调试命令示例 |
|----------|------|------------------|
| `IqStore` | store.js | `IqStore.state`、`IqStore.user()`、`IqStore.hasPerm('bank.write')` |
| `IqBank` | engine.js | `IqBank.all().length`、`IqBank.byId('SRV-001')`、`IqBank.overview()` |
| `IqEngine` | engine.js | `IqEngine.stats()`、`IqEngine.buildPaper({count:10})` |
| `IqUI` | ui.js | `IqUI.toast('测试')`、`IqUI.modal({title:'x',html:'y'})` |
| `IqApp` / `IqAdmin` | app.js / admin.js | `IqApp.route`、`IqApp.practice`、`IqApp.exam` |

### 3.4 数据模型（localStorage 键 `iqz.state.v1`）

```js
{
  version: 1,
  user: { name, role, dept, loginAt },        // role: super_admin|trainer|employee|partner
  customQuestions: [],                        // 管理端新增/导入的题目
  questionStatus: {},                         // qid -> 'draft'（缺省=published；另有 archived）
  questionEdits: {},                          // qid -> 覆盖字段（预留）
  deletedQuestions: [],                       // 被删除的内置题 id
  progress: { [qid]: { seen, right, wrong, fav, lastAt, lastResult } },
  wrong:    { [qid]: { count, lastAt, resolved, resolvedAt } },
  practiceLog: [ { id, mode, scope, total, right, wrong, durationSec, ids, endedAt } ],
  exams:    [ { id, taskId, scope, total, right, wrong, pending, got, full, percent,
                passLine, passed, durationSec, autoSubmit, detail[], submittedAt } ],
  tasks:    [ { id, title, category, count, minutes, passScore, deadline, roles[],
                allowRetake, status, createdBy, createdAt } ],
  notes:    { [qid]: '学习笔记' },
  settings: { dailyGoal, instantJudge, autoNext, shuffleOptions },
  meta:     { activeDates[], streak, lastActiveDate },
  audit:    [ { at, by, msg } ]               // 管理端操作日志
}
```

另一个键 `iqz.draft.v1` 保存**未交卷的考试草稿**（刷新后可续考）。

**注意**：题库数据**不进** localStorage，它以 JS 文件形式加载。因此 localStorage 的 5 MB 上限只影响学习记录，不会被题库挤爆。

### 3.5 计分规则（`IqEngine.TYPE_SCORE`）

| 题型 | 权重 | 判分方式 |
|------|------|----------|
| 单选 `single` | 1 | 自动判分 |
| 多选 `multi` | 1.5 | 自动判分（集合完全相等才算对） |
| 判断 `judge` | 1 | 自动判分 |
| 简答 `short` | 2 | 参考答案 + **自评** |
| 场景 `scenario` | 3 | 参考答案 + **自评** |

百分制 = 得分 / 满分 × 100，保留 1 位小数。

## 4. 代码地图：改需求时改哪里

| 需求 | 改动位置 | 说明 |
|------|----------|------|
| 换主题色 / 字号 / 圆角 | `assets/css/main.css` 的 `:root` 变量块 | `--brand` 是主色；深色模式在 `body.dark` 块覆盖同名变量 |

| 改统计口径 / 图表 | `engine.js` → `Engine.stats()`；图表画法在 `ui.js` → `donut/barChart/radar/trendChart` | 手写 SVG，无图表库 |
| 改导入校验规则 | `admin.js` → `validateQuestions()`（运行时）；`build-bank.mjs` → `validate()`（构建期） | **两套需同步修改** |

## 5. 题库维护（日常最主要的工作）

### 5.1 三种维护方式

| 方式 | 适用 | 操作 | 生效范围 |
|------|------|------|----------|
| **A. 改源文件（推荐）** | 团队协作、版本管理 | 改 `data/<品类>.json` → `node tools/build-bank.mjs` → 刷新页面 | 所有人（随文件分发） |
| **B. 管理后台编辑** | 快速修正、临时加题 | `admin.html` → 题库管理 → 编辑 / 新增 / 导入 | **仅当前浏览器** |
| **C. CSV 批量导入** | 从 Excel 来 | 管理后台 → 批量导入 → 下载模板 → 填好另存 CSV UTF-8 → 上传 | 仅当前浏览器 |

> ⚠️ **关键区别**：方式 B/C 改的是**浏览器本地覆盖层**（`customQuestions`），不会回写 `data/*.json`。要让改动惠及所有人，必须走方式 A；或把本地导出 JSON 后再落到 `data/`。

### 5.2 构建与校验命令

```powershell
node tools/build-bank.mjs --check    # 只校验（提交前自检 / CI 用）
node tools/build-bank.mjs            # 校验 + 生成 assets/js/core/bank.js
```

校验内容（不通过会中止构建并列出行号级错误）：

- 题号唯一性与格式（`前缀-序号`）
- `category` / `type` / `difficulty` / `security` 枚举合法性
- 答案键必须存在于选项中；多选题答案 ≥ 2 项；单选题恰好 1 项
- 简答/场景题的 `options` 必须为 `null`、`answer` 必须为文本
- 缺失解析 / 溯源 / 人群 → 警告（不阻断构建）

构建完成后会打印**题型、难度、密级分布表**，可直接对照规范检查配比。

### 5.3 出题红线（详见 `BANK_SCHEMA.md`）

1. 题干里的系列名、型号、参数必须真实，以汇川官网 / 官方手册为准，**禁止编造**；
2. 每题必须有解析，且解析要说明**干扰项错在哪**；
3. 每题必须写 `source`（资料名 + 章节 + 链接）；
4. 密级：`public`（可对客户/代理商）/ `internal`（仅内部）/ `confidential`（仅超管与讲师）；
5. 难度配比建议：初级 40% / 中级 40% / 高级 20%。

### 5.4 新增品类操作清单（照着做）

```
1. 新建 data/robot.json（按 BANK_SCHEMA.md 的字段规范）
2. store.js  CATEGORIES 数组加一项：{ key:'robot', name:'工业机器人', short:'机器人', color:'#8b5cf6', desc:'...' }
3. tools/build-bank.mjs  CATS 加 'robot'，PREFIX 加 robot:'RBT'
4. node tools/build-bank.mjs
5. 刷新页面，检查：仪表盘雷达图出现新轴、刷题筛选出现新品类、统计表出现新行
```

## 6. 权限与密级机制

### 6.1 四级角色

| 角色 key | 名称 | 权限概要 |
|----------|------|----------|
| `super_admin` | 超级管理员 | 全部功能；题库全生命周期；可见涉密题库与全部报表 |
| `trainer` | 培训讲师 | 题库维护审核、批量导入、发布考试任务、团队报表 |
| `employee` | 内部员工 | 内部题库刷题与考试、个人数据 |
| `partner` | 代理商/客户 | 仅公开题库、被指派的考试任务、个人数据 |

权限项常量（`store.js` → `ROLE_DEFS[].perms`）：
`quiz` `exam` `bank.read` `bank.write` `bank.review` `bank.import` `task.write` `report.all` `report.self` `user.manage` `security.public` `security.internal` `security.confidential`

### 6.2 密级隔离的实现位置（重要）

```js
// store.js
maxSecurity()        // 当前角色可见的最高密级（public=1 / internal=2 / confidential=3）
canSeeSecurity(sec)  // 单题级判断

// engine.js
Bank.all()           // ← 唯一对外出口，已按密级过滤
Bank.raw()           // ← 不过滤，管理端与管理统计使用
Bank.byId(id)        // ← 用 raw()，不做密级过滤（见"坑 3"）
```

**设计意图**：越权内容在**数据加载阶段**就被排除，不进入前端内存、不出现在 DOM，不是"界面隐藏"式伪隔离。

## 8. 已知限制与坑（接手务必先读）

### 坑 1：`file://` 与 `http://` 数据不互通 ⭐最常见

浏览器把 `file:///E:/...` 与 `http://localhost:8080` 视为**不同源**，localStorage 各自独立。

现象：用双击方式练了 50 题，换成 `serve.mjs` 打开后发现"数据全没了"。
处理：**固定一种访问方式**并在团队内统一；迁移数据用「个人设置 → 导出全部数据 / 导入数据」。

### 坑 2：清浏览器数据 = 清库

学习记录、自定义题目、考试任务都在 localStorage。清理浏览器数据、换浏览器、换电脑都会丢。
处理：定期导出备份；正式使用请上二期后端版本。

### 坑 3：`Bank.byId()` 不做密级过滤

`Bank.byId(id)` 基于 `raw()`，任何角色都能取出任意题目的对象。
现状：所有 UI 出口（错题本、收藏、统计、组卷）都额外调用了 `canSeeSecurity()` 过滤，因此**界面不会泄露**。
约束：**新增功能时如果直接用 `Bank.byId()` 展示题目，必须自己补 `canSeeSecurity()` 判断**。更稳妥的做法是改用 `Bank.all()` 里筛选出的对象。

### 坑 4：管理端的编辑是"覆盖层"，不会回写源文件

管理后台改题 → 存进 `customQuestions`（同 id 覆盖内置题）。重新执行 `build-bank.mjs` **不会**覆盖这些本地编辑；只有「恢复出厂」会清掉。
处理：定稿的题目请落到 `data/*.json`，保持"源文件是唯一真相"。

### 坑 5：删除内置题后，界面上无法恢复

删除内置题会写入 `deletedQuestions`，管理端「审核与上线」页没有"恢复删除"的入口（`IqStore.restoreQuestion()` 已实现但未接 UI）。
处理：误删后执行「个人设置 → 恢复出厂」找回（会同时清空学习记录）；或由开发者手工清 `deletedQuestions`：

```js
// 浏览器控制台
IqStore.state.deletedQuestions = []; IqStore.save(); location.reload();
```

### 坑 6：考试计时不受后台节流影响（设计说明，非缺陷）

浏览器会限制后台标签页的 `setInterval`。本工具的倒计时**基于 `startAt` 时间戳计算剩余时间**，只用定时器刷新显示，所以切到后台、切换页面都不会导致计时失真或凭空扣时间。刷新页面会从 `iqz.draft.v1` 恢复草稿继续作答。

### 坑 7：两套导入校验需同步维护

- 构建期：`tools/build-bank.mjs` → `validate()`（严格，错误即中止）
- 运行期：`admin.js` → `validateQuestions()`（宽松，分"错误/提示"两级，错误项跳过）

改动字段规范时**两处都要改**，否则会出现"文件能构建但导入报错"或反之。

### 坑 8：浏览器兼容性约束

代码刻意保持 ES5+ 语法（`var`、无箭头函数、无可选链、无 ES module），目的是：

- 支持 `file://` 直接打开（`<script type="module">` 在 `file://` 下会被 CORS 拦截）；
- 兼容内网仍存在的旧内核浏览器。

**新增代码请沿用此风格**，不要引入 `import/export`、`?.`、`??`。

### 坑 9：题库规模与性能

当前 986 题 → `bank.js` 约 1.3 MB（实测解码 30ms，全量加载无感）。设计余量约 3000 题；超过后建议按品类拆分按需加载。
超过后建议：按品类拆分 `bank-<cat>.js` 按需加载，或转后端分页查询（列表页已做 20 条/页分页）。

### 坑 10：导出功能依赖 Blob 下载

CSV/JSON 导出用 `Blob + a[download]`。个别内嵌 WebView（如某些 App 内置浏览器）可能拦截下载，此时请改用桌面浏览器操作管理端。

### 坑 11：单机版的"团队报表"其实是本机数据

`admin.html → 数据报表` 的"个人维度"只能统计**当前浏览器**中的数据。页面底部已注明。真正的团队报表需要二期后端。**不要用这一页的数据向领导汇报"全公司学习情况"**。

### 坑 12：字体未内置

样式使用系统字体栈（PingFang SC / 微软雅黑 等），未打包 webfont。内网 Linux 客户端若缺少中文字体，界面可能回退到衬线字体 —— 属预期行为，无需修复。

## 9. 二期演进建议

### 9.1 演进路线

```
一期（当前）：纯前端 + localStorage  →  验证题库与流程
   ↓  只替换 store.js 一个文件
二期：前端页面不动 + 后端 API + 数据库（用户体系 / SSO / 团队报表 / 跨端同步）
   ↓
三期：AI 出题答疑、视频联动、积分闯关、知识库联动（见开发规划方案 §九）
```

**这是本工具最重要的架构红利**：所有页面都只通过 `IqStore` 读写数据，把 `store.js` 换成 API 适配层即可，`app.js` / `admin.js` / `engine.js` 无需改动。

### 9.2 后端接口契约草案（供二期直接使用）

| 方法 | 路径 | 说明 | 对应一期方法 |
|------|------|------|--------------|
| POST | `/api/auth/login` | 登录（对接企业微信/钉钉/CAS） | `IqStore.login()` |
| GET | `/api/auth/me` | 当前用户与权限 | `IqStore.user()` / `roleDef()` |
| GET | `/api/questions?category=&type=&difficulty=&status=` | 题库查询（服务端按密级过滤） | `IqBank.filter()` |

## 11. 排障手册

| 症状 | 可能原因 | 处理 |
|------|----------|------|
| 页面白屏 | 脚本未按顺序加载 / `bank.js` 损坏 | F12 看 Console；执行 `node tools/build-bank.mjs` 重建 |

| 管理后台提示无权访问 | 当前身份不是管理员/讲师 | 右上角切换身份，或退出后用超级管理员登录 |

| 图表显示很小 / 留白多 | 超宽屏下图表受 `max-width` 约束居中显示 | 预期行为，可调 `ui.js` 里的 `max-width` 系数 |

## 13. 变更记录：人群模型、填空题与试卷导出（V1.2）

### 13.1 一句话概括

适用人群由「销售 / 技术工程师 / 售后运维 / 合作客户」调整为 **「销售 / 技术 / 采购 / 合作客户」**；新增**填空题**题型；**销售与采购只考查客观题**；管理员与技术人员可在模拟考试页**一键组 20 题试卷并导出 PDF / 打印**。

### 13.2 接手必须知道的 6 件事

1. **人群标识**：`sales` / `engineer` / `purchase` / `partner`。旧数据里的 `service` 已迁移为 `engineer`，三处保留兼容：`IqStore.ROLE_ALIAS`（前端）、`server/db.mjs` 种子归一化（后端）、`tools/migrate-roles.mjs`（数据迁移脚本）。
2. **题型共 6 种**：`single` / `multi` / `judge` / `fill` / `short` / `scenario`，分值权重 `1 / 1.5 / 1 / 1.5 / 2 / 3`（`IqEngine.TYPE_SCORE`、`server/db.mjs` 的 `TYPE_SCORES`）。
3. **硬约束**：`roles` 含 `sales` 或 `purchase` 的题目，`type` 只能是前四种客观题。三处校验会拦截：`tools/build-bank.mjs`（构建）、`server/db.mjs`（种子导入）、`assets/js/admin.js`（管理端导入与编辑器）。
4. **填空题数据格式**：`options` 为 `null`，`answer` 是**非空字符串数组**，长度必须等于题干中 `____` 的空位数；判分逐空归一化比对（去空白、全角转半角、小写），**全部空正确才得分**；管理端用竖线 `|` 分隔各空答案。
5. **试卷导出是纯前端能力**（`assets/js/paper.js`），后端无需新增接口。导出走**浏览器打印管线**产出 PDF（打印对话框中选择「另存为 PDF」），零依赖、零体积增量、中文由浏览器渲染；默认文件名经隐藏 `iframe` 的 `document.title` 传递。
6. **面板权限**：按 `task.write` 显示，仅超级管理员与培训讲师可见；组卷只使用当前账号可见密级的题目。

## 14. 变更记录：知识库模块（V2.0）

### 14.1 一句话概括

新增**结构化知识库**：五大品类 × 七个主题（产品介绍 / 选型知识 / 参数设置 / 安装调试 / 常见故障 / 客户高频问答 / 行业应用话术），支持全文检索、分类浏览、**知识 ↔ 题目双向关联**、学习记录与新人三阶段学习路线；管理端提供内容块可视化编辑器与学习统计。
AI 客户话术对练为二期能力（`ai_practice_record` 表已建，接口与页面预留，见设计文档 §8）。

### 14.2 接手必须知道的 5 件事

1. **数据链路**：`data/knowledge/<品类>.json` → `node tools/build-knowledge.mjs` → `assets/js/core/knowledge.js`（挂 `window.IqKnowledgeData`）；后端启动时同样读取这些 JSON 并 upsert 到 `knowledge` 表。
2. **正文是结构化内容块数组，不是 HTML**：共 10 种块类型（`h/p/list/table/tip/steps/faq/script/code/img`），用户端渲染在 `assets/js/kb.js` 的 `renderBlocks()`，管理端编辑器产出同结构数据——改渲染只需改一处。
3. **学习记录**存在 `state.knowledge[知识编号]`（`readSeconds / readCount / finished / fav / lastReadAt`），与题库进度同一容器，`导出全部数据` 会一并带走。
4. **密级复用现有机制**：`partner` 只能看到 `public` 条目。API 模式由服务端 SQL 过滤；本地模式由 `S.canSeeSecurity()` 过滤。含 `partner` 人群的条目在前端与构建脚本中都被强制要求 `security=public`。
5. **管理端在 API 模式下是异步的**：`S.kbStats()`、`S.kbImport()` 返回 Promise，必须用 `after()` 包装（与题库保存逻辑一致）；`S.kbList/kbById/kbMeta/kbRoute` 在两种模式下都是同步的（数据已在初始化时一次性拉入内存）。

> 单机模式的学习统计只统计**本机浏览器**的数据（`S.kbStats().localOnly === true`）；全员统计需要 API 模式。
