# 知识库模块设计说明（V2.0 · 知识库 + AI 对练一期）

> 本文是知识库模块的**唯一契约文档**：数据模型、接口清单、前端 API、页面结构、权限规则。
> 所有前端页面、后端接口、题库数据生产都必须以本文为准。
>
> 本轮范围：**知识库模块全量落地**；AI 客户话术对练模块按本文 §8 预留（表结构已建，接口与页面二期实现）。

---

## 1. 目标与边界

把静态 PDF 文档变成「碎片化、结构化、可检索、可关联刷题」的知识库，解决新人「看文档记不住、没人带、问客户答不上」。

| 做 | 不做（二期） |
|----|--------------|
| 知识库数据模型 + 构建脚本 | AI 话术对练对话引擎 |
| 用户端：检索、分类浏览、详情、关联刷题、收藏、学习记录、新人路线 | 对练评分与纠错 |
| 管理端：增删改、上下线、归档、批量导入、学习统计 | 对练场景库内容 |
| 权限与密级强校验（前后端） | 外部大模型接入 |
| 双模式：`api=0` 离线只读 / `api=1` 完整落库 | — |

## 2. 数据模型

### 2.1 分类体系

**一级（品类）**：复用题库枚举 `servo | inverter | plc | hmi | io`

**二级（主题）**：

| key | 名称 | 说明 |
|-----|------|------|
| `intro` | 产品介绍 | 系列定位、型号命名、卖点 |
| `selection` | 选型知识 | 选型步骤、参数换算、常见搭配 |
| `param` | 参数设置 | 关键参数、调试步骤、软件工具 |
| `install` | 安装调试 | 接线、散热、EMC、上电流程 |
| `fault` | 常见故障 | 故障码、现象→原因→处理 |
| `faq` | 客户高频问答 | 客户最常问的问题与标准答法 |
| `script` | 行业应用话术 | 面向行业/场景的沟通话术与案例 |

### 2.2 知识条目 JSON（`data/knowledge/<category>.json`）

```jsonc
{
  "id": "KB-SRV-001",              // 知识编号：KB-<品类前缀>-<三位序号>
  "category": "servo",             // 一级分类
  "topic": "selection",            // 二级分类
  "title": "SV660N 与 SV670N 怎么选：一套可复用的选型三步法",   // ≤ 60 字
  "summary": "一句话说明这篇讲什么、解决什么问题（≤ 80 字）",
  "tags": ["SV660N", "SV670N", "选型"],   // 2–6 个
  "roles": ["sales", "engineer"],          // sales|engineer|purchase|partner
  "security": "public",                    // public|internal|confidential
  "readMinutes": 6,                        // 预计阅读时长（分钟）
  "level": 1,                              // 1 入门 / 2 进阶 / 3 深入
  "sortOrder": 10,                         // 新人学习路线排序（越小越靠前，跨品类全局排序）
  "content": [ /* 结构化内容块，见 2.3 */ ],
  "relatedQuestions": ["SRV-001", "SRV-012"],  // 关联题库题号（必须真实存在）
  "source": { "title": "汇川技术 SV660N 系列伺服驱动器用户手册", "url": "https://www.inovance.com/..." },
  "updatedAt": "2026-09-15"
}
```

### 2.3 内容块（`content` 数组元素）

| type | 字段 | 渲染 |
|------|------|------|
| `h` | `text` | 小标题 |
| `p` | `text` | 段落（支持 `**加粗**`、`` `代码` ``） |
| `list` | `items: string[]`、`ordered?: bool` | 列表 |
| `table` | `head: string[]`、`rows: string[][]` | 表格（横向可滚动） |
| `tip` | `text`、`kind?: "info"｜"warn"｜"danger"` | 提示框 |
| `steps` | `items: string[]` | 编号步骤（强调流程） |
| `faq` | `q: string`、`a: string` | 问答对（话术类主力块） |
| `script` | `scene: string`、`bad: string`、`good: string` | 话术对比：场景 + 错误说法 + 标准说法 |
| `code` | `text`、`lang?: string` | 代码 / 参数表原文 |
| `img` | `src`、`caption?` | 图片（`src` 相对路径或 data URI；一期内容以表格/文字为主） |

## 3. 后端接口清单（`server/app.mjs`）

统一响应体 `{ code, message, data }`；权限与密级在 SQL 层强制（复用 `scopeClause(user)`）。

### 3.1 用户端（需登录）

| 方法 | 路径 | 权限 | 入参 | 返回 |
|------|------|------|------|------|
| GET | `/api/knowledge` | 登录 | `category, topic, keyword, tag, level, page=1, page_size=20` | `{ items, total, page, page_size }`（items 不含 content 正文，含 summary） |
| GET | `/api/knowledge/meta` | 登录 | — | `{ categories:[{key,name,count}], topics:[{key,name,count}], tags:[...], stats:{ total, byCategory, byTopic, bySecurity, myFinished, myRead } }` |
| GET | `/api/knowledge/route` | 登录 | — | `{ stages:[{ key, title, desc, items:[{ knowledgeNo, title, category, topic, readMinutes, finished, level }] }] }` |
| GET | `/api/knowledge/:no` | 登录 | — | 条目全量（含 `content`、`relatedQuestions`；关联题目回带 `{ questionNo, stem, type, difficulty }` 摘要） |
| POST | `/api/knowledge/:no/read` | 登录 | `{ seconds, finished? }` | `{ record:{ readSeconds, readCount, finished, lastReadAt } }` |
| POST | `/api/knowledge/:no/fav` | 登录 | `{ fav: bool }` | `{ fav: bool }` |
| GET | `/api/me/knowledge` | 登录 | `recent=10` | `{ records:[...], favs:[...], recent:[...], stats:{ readCount, finishedCount, totalSeconds } }` |

### 3.2 管理端（`bank.write`）

| 方法 | 路径 | 入参 | 返回 |
|------|------|------|------|
| GET | `/api/admin/knowledge` | `keyword, category, topic, status, security, page, page_size` | `{ items, total }`（含 content，便于编辑） |
| POST | `/api/admin/knowledge` | 条目 JSON（见 §2.2） | `{ knowledgeNo }` |
| PUT | `/api/admin/knowledge/:no` | 条目 JSON | `{ updated: true }` |
| DELETE | `/api/admin/knowledge/:no` | — | `{ deleted: true }`（软删） |
| POST | `/api/admin/knowledge/:no/status` | `{ status }` | `{ status }` |
| POST | `/api/admin/knowledge/import` | `{ items:[...], mode:"skip"｜"overwrite" }` | `{ imported, updated, skipped, errorCount, errors:[{ row, knowledgeNo, field, message }] }` |
| GET | `/api/admin/knowledge/stats` | — | `{ total, byCategory, byTopic, bySecurity, byStatus, readTop:[{ knowledgeNo, title, readers, avgSeconds }], userStats:[{ userId, name, dept, readCount, finishedCount, totalSeconds }] }` |

**校验规则（服务端必须执行）**

1. `knowledge_no` 唯一，格式 `KB-(SRV|INV|PLC|HMI|IO)-\d{3}`；
2. `category` / `topic` / `security` / `status` 必须在枚举内；
3. `content` 必须是非空数组，元素 `type` 在支持列表内；
4. `relatedQuestions` 中的题号必须存在于 `question` 表（不存在的剔除并在 errors 中提示）；
5. `roles` 含 `partner` 时 `security` 必须为 `public`；
6. 非 `super_admin` / `trainer` 的写操作一律 403。

## 4. 前端数据层 API（`assets/js/core/store.js` 扩展）

本地模式与 API 模式**同名同签名**；`api-store.js` 负责转接。

```js
// 只读（两种模式下都是同步的：数据在初始化时已一次性拉入内存）
S.kbList(cond)        // cond: {category, topic, keyword, tag, level, security, status,
                      //        page, page_size, includeUnpublished}
                      //   → { items, total, page, page_size }；不传 page_size 时返回全部条目
                      //   includeUnpublished=true 时含草稿与归档（管理端用）
S.kbById(no)          // → 条目（含 content）
S.kbMeta()            // → { categories, topics, tags, stats }
S.kbRoute()           // → { stages:[...] }
S.kbRaw()             // → 合并后的全部条目（含管理端覆盖层，未做密级过滤）
// 学习行为（本地写 state.knowledge；API 模式同时上报服务端）
S.kbMarkRead(no, seconds, finished)   // → 记录
S.kbToggleFav(no)                     // → bool
S.kbMyRecords()                       // → { records, favs, recent, stats }
// 管理端（本地模式写 state.customKnowledge / knowledgeEdits，与题库一致）
S.kbSaveItem(item)    // 新增/更新（按 id 判定）
S.kbDeleteItem(no)    // 软删（本地标记）
S.kbSetStatus(no, status)
S.kbImport(items, mode)  // → { imported, updated, skipped, errorCount, errors }（API 模式返回 Promise）
S.kbStats()              // → { total, byCategory, byTopic, bySecurity, byStatus, readTop, userStats, localOnly }
                         //   API 模式返回 Promise，调用方需用 admin.js 的 after() 包装
S.kbSuggestNo(category)  // → 下一个可用编号，如 KB-SRV-011
```

### 4.1 导出 PDF / 打印（`IqKB` 暴露，管理端复用）

```js
IqKB.exportPdf(no, opts)  // → 期望的 PDF 文件名；内部调用 IqPaper.printHtml(html, docTitle)
IqKB.printDoc(no, opts)   // → 同一版式与实现，仅 UI 提示语不同（直接打印）
IqKB.docHtml(item, opts)  // → 独立文档 HTML（A4 版式，含关联题与答案）
```

**为什么 PDF 走打印管线**：本项目有三个硬约束 —— 零第三方依赖、内网离线、中文排版。
jsPDF / pdf-lib 一类方案必须内嵌中文字体子集（通常数 MB），会破坏离线包的精简性；
浏览器打印管线则可以「零依赖 + 零体积增量」产出 PDF，中文由浏览器渲染。

实现要点：

1. `@page{size:A4;margin:16mm 14mm 18mm}` 控制纸张与页边距；
2. `*{print-color-adjust:exact}` 让提示框、话术对比、表头等浅色底纹在 PDF 中保留；
3. **文件名**：把期望的文件名写入隐藏 iframe 的 `document.title`，浏览器「另存为 PDF」会以它作为默认保存名；
4. 分页控制：`page-break-inside:avoid` 用于问答 / 话术 / 关联题块，`page-break-after:avoid` 用于小标题。

本地状态新增键（`iqz.state.v1` 内）：

```jsonc
{
  "knowledge": {
    "KB-SRV-001": { "readSeconds": 320, "readCount": 2, "finished": true, "finishedAt": "...", "fav": false, "lastReadAt": "..." }
  },
  "knowledgeOverrides": { "KB-SRV-001": { /* 管理端编辑覆盖层 */ } },
  "knowledgeDeleted": ["KB-SRV-003"]
}
```

## 6. 权限与密级

| 角色 | 可见知识 | 学习行为 | 管理端 |
|------|----------|----------|--------|
| `super_admin` | 全部（含涉密） | ✅ | ✅ 全部 |
| `trainer` | 全部（含涉密） | ✅ | ✅ 全部 |
| `employee`（含销售/采购/技术） | `public` + `internal` | ✅ | ❌ |
| `partner`（合作客户） | 仅 `public` | ✅（只读学习） | ❌ |

- 密级在**数据层过滤**：API 模式下由服务端 SQL 过滤；本地模式下由 `S.canSeeSecurity()` 过滤。
- 合作客户不显示任何管理入口，也看不到内部资料（含关联题号中越权的题目摘要）。

## 7. 构建与数据生产

- 数据源：`data/knowledge/<category>.json`（5 个文件，每品类 10 篇，共 **50 篇**）
- 构建脚本：`node tools/build-knowledge.mjs [--check]` → 产出 `assets/js/core/knowledge.js`（挂 `window.IqKnowledgeData`）
- 校验项：编号唯一与格式、枚举合法性、内容块类型、`relatedQuestions` 是否存在于 `bank.js`、`partner` 与 `security` 约束、摘要与标题长度、`content` 非空、标签数量
- 后端种子：`server/db.mjs` 启动时读取 `data/knowledge/*.json` 并 upsert 到 `knowledge` 表
