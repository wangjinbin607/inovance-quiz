## 五、联调中发现并修复的缺陷

> 这 5 个问题都是**只有真正把前后端跑起来才会暴露**的，静态审查难以发现。

### 缺陷 1：登录接口被认证中间件拦截（后端，阻断级）

- **现象**：`POST /api/auth/login` 返回 `401 未登录或登录已过期`，任何人都无法登录
- **原因**：认证检查对所有路由无条件执行，未区分匿名接口
- **修复**：路由表引入 `isPublic` 标记，仅登录接口放行；`logAudit` 对空用户做了空值保护
- **回归**：错误密码返回 401、正确密码返回 token ✅

### 缺陷 2：`user` 表缺少 `deleted_at` 列（后端，阻断级）

- **现象**：登录时报 `no such column: deleted_at`
- **原因**：建表脚本与规格书不一致（规格书要求软删除列），且 `CREATE TABLE IF NOT EXISTS` 不会更新已存在的表
- **修复**：schema 补齐该列，并新增**轻量迁移函数** —— 启动时检查并 `ALTER TABLE ADD COLUMN`，避免已部署库重建丢数据
- **回归**：旧库自动补列，登录恢复正常 ✅

### 缺陷 3：题库不含答案，前端本地判题失效（契约级）

- **现象**：API 模式下点击判断题选项报 `Cannot read properties of undefined (reading 'indexOf')`，且无法判题 —— 页面卡死在第 1 题
- **原因**：后端出于防作弊默认不下发 `answer`，而**现有前端在练习模式做本地即时判题与解析展示**，必须拿到答案
- **修复**：
  - 题库接口新增 `withAnswer=true`（默认 false），练习场景显式请求
  - 管理端接口直接返回答案（用于编辑回显）
  - **考试流程不受影响**：`/api/exams/start` 下发的试卷始终不含答案，交卷由服务端判分，成绩不可篡改
- **回归**：157 题全部带答案与解析；考试试卷 `paperHasAnswer === false` ✅
- **遗留说明**：见第六节"已知限制 1"

### 缺陷 4：练习记录未回传服务端（契约级）

- **现象**：练习完成后 `practiceLog` 为空，服务端无记录
- **原因**：现有前端在本地组卷（未调用 `/api/practice/paper`），因此 `practice_session` 表中没有会话行，`finish` 接口更新 0 行
- **修复**：`finish` 接口在会话不存在时**自动补建**（用会话内最早一条答题记录作为开始时间），前端补传 `mode`/`scope`
- **回归**：练习完成后服务端生成会话记录，列表可查 ✅

### 缺陷 5：越权审计噪声（设计缺陷）

- **现象**：普通员工每次登录都产生一条 `security.denied /api/admin/questions` 审计记录，看起来像有人在扫描接口
- **原因**：前端加载题库时先试探管理端接口，无权限被拒后回退
- **修复**：前端按 `/api/auth/me` 返回的 `permissions` 决定调用哪个接口（有 `bank.read` 才走管理端）
- **回归**：修复后登录仅产生 `auth.login` + `question.bank_load` 两条正常审计 ✅

## 六、已知限制与后续建议

### 限制 1：前端内存中持有题库答案（架构级）

现有前端为纯前端应用，题库全量加载到浏览器，练习判题在本地完成。因此：

- 普通学员理论上可通过 F12 查看题目答案；
- **但成绩不可篡改** —— 交卷与判分完全在服务端，前端只负责展示；
- 密级隔离有效 —— 服务端不下发越权题目，学员无法看到更高密级的题。

**建议**：二期将练习判题也改为服务端（提交答案 → 服务端返回判定与解析），前端不再持有答案。改动集中在 `bindQuestionCard` 的判定调用处，页面结构不变。

### 限制 2：服务端计时与断点续考的浏览器兼容

考试倒计时以服务端下发的 `remainingSec` 为准（不信任本地时间）。刷新页面会从服务端恢复作答与剩余时间。已验证正常。

### 限制 3：Node 参考实现 ≠ 生产实现

`server/` 是**为联调与自测提供的零依赖参考实现**（SQLite + 原生 HTTP），接口契约与《后端开发规格说明书》一致。生产环境请按规格书使用 **MySQL + Spring Boot**，本实现的 SQL 层已按同构模型设计，便于迁移。

### 建议的下一步

| 优先级 | 事项 | 说明 |
|:------:|------|------|
| P0 | 用 MySQL 实现生产后端 | 按规格书第一章建表、第三章接口，本参考实现可作为对照 |
| P0 | 将练习判题上移服务端 | 消除限制 1，前端改为提交作答、展示服务端判定结果 |
| P1 | Excel 导入（EasyExcel） | 参考实现目前支持 JSON 导入，Excel 需按规格书 §2.4 实现 |
| P1 | SSO / 企业微信免登 | 数据库已预留 `sso_*` 表结构 |
| P2 | 题库变更的乐观锁 | 多人同时编辑同一题时的覆盖问题 |

### 9.4 本轮发现并修复的问题

**问题 1：题库扩充后前端只加载到 200 题（严重）**

- **现象**：后端已有 300 题，前端登录后 `INOVANCE_BANK` 只有 200 题，且分布异常（plc 只有 20 题）
- **原因**：`api-store.js` 用固定 `page_size=200` 单次拉取题库，而服务端 `page_size` 上限就是 200，超出的题目被静默截断
- **修复**：改为**分页循环拉取**（`fetchAllQuestions()`，按 `total` 判断是否继续取下一页），管理端与只读接口共用同一实现
- **回归**：员工端加载 **275 题**、五品类各 55 题；超管端 300 题
- **教训**：分页上限是"静默截断"的典型来源 —— 数据量增长时不会报错，只会少数据

**问题 2：后端种子只导入主文件，忽略批次文件（严重）**

- **现象**：重启后端后题库仍显示 172 题（旧数据），新增的 130 题未入库
- **原因**：`server/db.mjs` 的 `seedQuestions()` 硬编码了 5 个主文件名（`servo.json` 等），不读取 `-2.json` 批次文件；而构建脚本读的是 `data/` 下全部 `.json`，两者不一致
- **修复**：改为读取 `data/` 下全部 `.json` 并排序，与构建脚本对齐
- **回归**：后端题库 302 行（300 有效 + 2 软删除），三种角色可见数正确

**问题 3：软删除的题目永久占用题号**

- **现象**：自动化测试反复失败在"新建题目"步骤；管理员删除题目后无法再用相同题号新建
- **原因**：删除是软删除（写 `deleted_at`），但 `question_no` 的唯一约束仍然生效；新建时的查重 SQL 也没有排除已删除记录
- **修复**：
  - 新建题目时若发现同题号已被软删除 → **复用该记录**（恢复并覆盖内容），而不是报冲突
  - 批量导入的 UPDATE 分支补上 `deleted_at=NULL`，避免"导入了但题目仍是删除状态"的静默问题
- **回归**：删除 → 重建同题号成功；冒烟测试恢复全绿

**问题 4：题库体检的重复题检测误报**

- **现象**：`IO-015` 与 `IO-018` 被报为疑似重复
- **核实**：两题前缀相同（"根据汇川官网 GL20 系列产品页…"）但考点完全不同（总线协议 vs 模块类型），属正常出题模式
- **原因**：初版算法只比对题干规范化后的**前 26 字**
- **修复**：改为两级判定 —— ① 全文规范化后完全一致 → 判定完全重复；② 同品类 + 长度差 ≤12 字 + 字符二元组 Dice 相似度 ≥88% → 判定高度相似
- **回归**：误报消失（0 组），同时保留对"改一个数字/换个说法"的真重复识别能力

**问题 5：练习与考试草稿跨账号串用**

- **现象**：同一浏览器切换账号后，会弹出"检测到未完成的练习"并恢复**上一个账号**的进度
- **原因**：草稿存在 localStorage（按浏览器隔离，不按账号隔离），恢复时未校验归属
- **修复**：草稿写入 `owner` 字段（当前登录账号），启动检查时校验归属，不匹配则静默清理
- **回归**：伪造他人草稿后刷新，不再提示且草稿被清除

> 这 5 个问题都只在"题库规模增长 + 多账号 + 反复操作"的组合下才会暴露 —— 单批 170 题、单账号测试时全部不可见。

**问题 6：参考答案与解析面板被整体右对齐（样式类名冲突）**

- **现象**（用户反馈）：刷题训练里主观题的「参考答案（自评判分）」面板中，短行如"参考答案要点："跑到右侧，长行虽因占满宽度看不明显，但整块文本实际是右对齐的
- **原因**：CSS 中 `.right` 既是**工具类**（`text-align: right`），又被复用作**语义类**（表示"回答正确"的绿底样式）。`<div class="answer-panel right">` 同时命中两条规则，于是"正确的面板"被顺带右对齐了；`.opt.right`（正确选项）同理
- **修复**：
  1. 语义类统一改名为 `is-correct` / `is-wrong`，与工具类彻底分离（CSS 13 处 + JS 8 处）
  2. 给 `.answer-panel`、`.ana`、`.src`、`.ref-answer`、`.opt .txt` 补 `text-align: left` 作为防御，即使将来有外部工具类干扰也不会跑偏
- **全面检查**（对应"全体检查并优化"）：
  - 全库检索 `answer-panel (right|wrong)`、`opt (right|wrong)`、`' right'`、`' wrong'` 等模式 → **0 处残留**
  - 复核其余工具类（`.center` `.small` `.muted` `.hidden` 等）与组件类是否存在同类同名冲突 → 无（`.tag.ok` `.bar.ok` 等均为复合选择器，不冲突）
  - 浏览器实测客观题与主观题两条路径：`qstem / optTxt / answerPanel / ana / src / title` 的计算样式 `text-align` **全部为 left**，且 `is-correct` / `is-wrong` 的状态色正常（正确项绿边、错选项红底）
  - 管理端题目预览与错题本解析弹窗复用同一渲染函数，已同步修复
